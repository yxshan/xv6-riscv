# xv6-riscv 模块方向与优先级评估

## 1. 评估目标

基于当前已经完成的模块基础设施，汇总未来可拓展方向，并从多维度评估优先级：

- 学习价值：能否帮助理解操作系统核心原理
- 架构契合：能否复用现有模块注册表、钩子、设备表
- 实现成本：改造量和实现难度
- 用户价值：是否能在 shell 中直接看到效果
- 风险控制：对核心路径的侵入程度
- 可验证性：是否容易用 QEMU 和测试程序验证

## 2. 评价维度与权重

| 维度 | 权重 |
|---|---|
| 学习价值 | 25% |
| 架构契合 | 20% |
| 实现成本 | 20% |
| 用户价值 | 15% |
| 风险控制 | 10% |
| 可验证性 | 10% |

每项按 1-5 分打分，5 分表示“最有利”。
总分越高，越适合优先实现。

## 3. 当前基础设施可用能力

已经具备的模块能力：

- 静态内核模块自动扫描
- `module_call` 通用系统调用
- 事件钩子：tick、syscall enter/exit、proc fork/exit
- `devsw` 完整文件操作接口
- 伪设备 `/sysinfo`
- 用户模块自动扫描
- 教学级动态模块加载

这些能力决定了不同模块的“架构契合”得分：

- 统计类模块：直接复用 `module_call`
- 追踪类模块：直接复用事件钩子
- 设备类模块：直接复用 `devsw`
- 文件系统类模块：需要触碰 `fs.c`
- 调度类模块：需要触碰 `scheduler()`
- 内存类模块：需要触碰 `vm.c` 和缺页路径

## 6. 优先级路线

### P0：近期优先

这些方向学习价值高、与现有架构契合、实现成本低：

1. 用户态 `strace`
2. 进程优先级调度
3. `sysinfo` 扩展与最小 `/proc`
4. 性能计数器
5. 符号链接
6. 伪设备体系完善
7. shell 增强

`strace` 最值得优先做，因为事件钩子已经存在，只需要把统计结果转成用户可见输出。

### P0 当前状态

以下 P0 项目已经完成并通过 QEMU 验证：

- 用户态 `strace`：`user/strace.c`
- 进程优先级调度：`setpriority` + `user/prio.c`
- `sysinfo` 扩展与进程列表：`SYSINFO_CMD_DUMP` + `user/procinfo.c`
- 性能计数器：`user/perf.c`
- 符号链接：`T_SYMLINK` + `ln -s`
- 伪设备体系：`/dev/sysinfo`、`/dev/stats`
- shell 增强：支持 `&&` 短路执行

### P1：中期重点

这些方向能显著提升系统能力，但需要更多核心改造：

1. 命名管道 FIFO
2. 完整 `/proc` 伪文件系统
3. MLFQ 调度
4. 写时复制 fork
5. 共享内存
6. 信号机制
7. 崩溃转储

### P2：进阶方向

适合已经熟悉 xv6 核心后继续深入：

1. 文件权限与用户/组
2. 需求分页与 `mmap`
3. 动态模块 ELF 化
4. 多磁盘支持

### P3：挑战方向

这些方向工程量较大，更适合作为长期目标：

1. VFS 与多文件系统挂载
2. 内核线程与 `clone`
3. 交换空间
4. 动态链接器
5. 网络协议栈
6. ASLR
7. 图形显示

## 7. 推荐选择策略

如果目标是“继续理解操作系统原理”：

推荐顺序为：

```text
strace -> 优先级调度 -> 符号链接 -> FIFO -> COW fork -> MLFQ
```

如果目标是“完善模块平台”：

推荐顺序为：

```text
性能计数器 -> /proc -> 动态模块 ELF 化 -> 多模块并行
```

如果目标是“做完整操作系统”：

推荐顺序为：

```text
/proc -> 权限与用户 -> VFS -> 网络 -> 动态链接
```

## 8. 落地建议

- 每个模块保持独立目录和独立测试
- 优先使用 `module_call` 暴露功能
- 需要文件接口的模块优先使用 `devsw`
- 需要跟踪行为的模块优先使用事件钩子
- 涉及调度的模块单独设计，避免破坏现有调度器
- 动态模块目前定位为演示和实验，不作为生产主路径

评分表只是参考，实际优先级应结合学习目标和项目方向动态调整。
